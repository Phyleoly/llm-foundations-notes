# 3. WordPiece

> 训练时关注候选 token 对语料目标的贡献；编码时通常使用最长匹配。

## 和 BPE 的区别

BPE 常用相邻对频率决定下一次合并。

WordPiece 通常从语料建模效果出发评价候选 token，而不是只看这一对出现了多少次。

需要注意：不同资料和实现对 WordPiece 训练细节的描述不完全一致。这里先记稳定的部分，不把它简单写成“另一种 BPE”。

## 训练

概念流程：

1. 准备能覆盖语料的基础符号；
2. 生成候选 subword；
3. 估计候选对语料目标的改善；
4. 选出贡献较大的候选加入词表；
5. 达到目标词表大小后停止。

具体分数要以实际 tokenizer 实现为准。

## 编码：Longest Match First

从左到右做贪心最长匹配：

1. 在当前位置找词表中最长的可匹配片段；
2. 输出这个 token；
3. 继续匹配剩余字符串；
4. 某一步无法匹配时，输出未知 token 或执行实现自己的回退策略。

很多实现使用 `##` 标记“只能出现在词中间的 token”：

```text
playing → play + ##ing
```

`##` 是词表约定，不是原始文本的一部分。

## 小例子

词表：

```text
play
player
##ing
##er
```

可能得到：

```text
playing → play + ##ing
player  → player
```

最长匹配是贪心策略，不保证等于某个全局概率目标下的最优切分。

## 记住

优点：

- 编码逻辑清楚；
- 最长匹配容易高效实现；
- `##` 可以区分词首和词内片段。

问题：

- 训练细节依赖具体实现；
- 贪心匹配不是全局搜索；
- 无法匹配时的行为依赖基础符号和回退策略。
