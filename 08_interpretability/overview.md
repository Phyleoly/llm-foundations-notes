# 可解释性的问题、对象与证据

> 状态：草稿

> 前置内容：[Token 到概率模型](../01_probability/01_token_probability_model.md)，理解模型根据上下文输出 next-token 分布即可。

本篇要回答：学习可解释性时，我们究竟在解释什么，又需要什么证据才能支持一个解释？

## 1. 先把“为什么”变成一个具体问题

“模型理解了什么”很难直接检验。更好的起点是固定模型、输入范围和行为指标，例如：

- 对同一条提示，为什么候选 token A 的 logit 高于 B？
- 某层 hidden state 中能否读出 token 的位置？
- 替换某个 attention head 的输出，是否改变候选答案的相对分数？
- 一组组件能否共同解释重复序列中的复制行为？

这些问题分别指向输出、表示、组件作用和计算机制。回答其中一个，不会自动回答其余问题。

对生成模型，还要说明解释的是哪一步预测。固定前缀下的 next-token 分数，与自由生成一整段文本，是不同的实验对象；后者会受到前面生成结果和采样过程的影响。

## 2. 几个可以交叉使用的分类维度

Interpretability 与 explainability 在文献中的用法并不完全统一。本章统一使用“可解释性”，并通过研究对象和证据说明具体含义。

| 维度 | 区分的问题 | 例子 |
| --- | --- | --- |
| 局部 / 跨样本解释 | 解释一个预测，还是某类输入上的规律 | 单条提示的归因；多个模板上的复制机制 |
| 输入输出 / 内部机制 | 只能改变输入并观察输出，还是能读取与干预内部量 | 删除词语；替换某层 activation |
| 内在可解释 / 事后解释 | 可理解结构是否来自模型设计，还是训练后另行分析 | 受约束的简单模型；对预训练 Transformer 的分析 |
| 表示 / 计算 | 关心信息如何编码，还是如何被后续计算使用 | 位置探针；位置相关信息的干预实验 |

这些是描述研究设置的维度，并非互斥的方法清单。机制可解释性侧重用内部组件、特征及其交互说明模型怎样完成某个计算；一个局部机制也需要检查是否能推广到其他样本。可参考 [Transformer Circuits 的数学框架](https://transformer-circuits.pub/2021/framework/index.html) 中对小型 attention-only 模型的分析。

## 3. 不同证据支持不同说法

以下区分是本章采用的工作框架，用来约束自己的结论；它不是对所有方法统一打分的等级表。

| 证据 | 可以支持的表述 | 还缺什么 |
| --- | --- | --- |
| attention 图或 activation 随输入变化 | 在这些样本中观察到某种模式 | 模式对输出是否有作用 |
| 探针在留出数据上预测成功 | 所选表示中存在该探针能利用的信息 | 原模型是否使用了同一信息 |
| 替换或消融 activation 后分数变化 | 在指定干预与上下文中，该位置对指标有影响 | 效应是否来自目标信息、是否有替代路径 |
| 组件与路径干预共同支持一个假说 | 候选机制解释了已测行为的一部分 | 完整性、失败案例和跨分布适用范围 |

探针本身也会学习，因而需要控制任务、简单基线和容量约束。[Hewitt 与 Liang（2019）](https://aclanthology.org/D19-1275/) 提出的 control tasks 是理解这一点的具体入口。

干预也不是自动正确的证据：替换位置不准确、对照改变了多个变量，或拼接出异常的内部状态，都可能使结论偏离原问题。具体方法见 [Activation Patching](./activation_patching.md)。

## 4. 用 NoPE 把三个问题分开

沿用 [NoPE 阅读路线](../02_representation/03_nope_reading_list.md)，可以把研究拆成：

1. **信息可读出吗？** 冻结模型，用 hidden state 预测 token 位置，并在留出序列上评估。
2. **信息怎样出现？** 分析 causal mask、输入分布和归一化怎样影响表示的统计量，并设计相应对照。
3. **模型使用它了吗？** 提出具体的位置信息假说，再设计尽量保留其他内容的干预，测量语言建模或位置敏感任务的变化。

第一步成功不等于第三步已经成立。第三步尤其需要处理内容信息与位置信息纠缠、干预分布变化等问题。这里是问题拆解示例，未新增实验结果。

## 5. 可读、正确与忠实是不同目标

- **可读性**：人能否理解这段解释或图。
- **任务正确性**：模型答案是否符合任务标准。
- **忠实性（faithfulness）**：解释是否反映模型产生该行为时的实际依赖与计算。

一个流畅的理由可以帮助读者理解答案，但它需要额外验证才能成为内部机制的证据。关于模型生成解释的局限，可读 [Turpin 等（2023）](https://arxiv.org/abs/2305.04388) 对特定提示偏差下 CoT 解释的研究；其结果不应被改写成“所有 CoT 都不忠实”。

同样，attention 权重描述了 Value 的混合系数，但输出还取决于 Value、输出投影和后续计算。理解争议时配对阅读 [Attention is not Explanation](https://aclanthology.org/N19-1357/) 与 [Attention is not not Explanation](https://aclanthology.org/D19-1002/)，检查各自的模型设置和解释标准。

## 6. 每篇解释先填写这五项

1. **行为**：模型版本、输入分布、预测位置和目标分数。
2. **对象**：输入 token、表示方向、head、MLP、SAE feature 或组件之间的路径。
3. **假说**：预期怎样传递或使用信息，以及什么结果会反驳它。
4. **证据**：观察、探针或干预；对应基线、对照和留出样本。
5. **边界**：已支持的范围、反例和仍可能成立的其他解释。
