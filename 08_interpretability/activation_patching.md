# Activation Patching：用替换实验检验局部作用

> 状态：草稿

> 前置内容：[可解释性的问题与证据](./overview.md)、[残差流与观察位置](./residual_stream_and_logit_lens.md)、[Token 到概率模型](../01_probability/01_token_probability_model.md)。

本篇要回答：把一次前向中的内部激活替换到另一次前向里，能够检验什么，又不能直接证明什么？

## 1. 定义一个受控的对比

选择一个模型已经表现出的行为，并构造输入对：

- **clean 输入** $x_c$：包含当前研究的信息。
- **corrupted 输入** $x_r$：按明确规则改变该信息，作为对照。

这里 corrupted 不要求输入是乱码或错误句子，它可以是另一个合理上下文。关键是写清两个输入的差异。首次练习优先选择 token 位置能够明确对齐的输入对，并实际检查 tokenizer 输出。

固定一个预测位置，设候选单 token 的 ID 为 $a$ 和 $b$。令模型在该位置输出 $z(x)\in\mathbb R^V$，其中 $V$ 为词表大小，定义分数：

```math
s(x)=z_a(x)-z_b(x).
```

在两个输入及所有干预运行中保持相同的候选顺序。正值表示相对更偏向 $a$；它不保证 $a$ 是整个词表中的最高分 token。若候选答案包含多个 token，应另行定义序列得分。

## 2. 三次前向各做什么

记 $h_{\ell,p}(x)\in\mathbb R^d$ 为某个已明确命名的层内观察点在位置 $p$ 的 activation；例如某层输入端的 residual stream。层号、位置和维度必须与实现对应。

1. 在 clean 输入上运行，保存 $h_{\ell,p}(x_c)$ 和基准分数 $s_c$。
2. 在 corrupted 输入上运行，记录分数 $s_r$。
3. 再次运行 corrupted 输入，在同一观察点用 clean activation 替换原值，然后继续计算所有受影响的下游节点，得到 $s_{\mathrm{patch}}$。

用记号表示第三次运行中的替换：

```math
h_{\ell,p}(x_r)\leftarrow h_{\ell,p}(x_c).
```

模型参数保持固定，改变的是本次运行中的内部值。每个待测位置从独立的基准前向开始，避免上一次替换影响下一次结果。缓存位置与替换位置必须一致，不能把 Norm 前的向量误放到 Norm 后。

## 3. 原始效应与归一化恢复量

先报告三个原始分数，再计算：

```math
\Delta s=s_{\mathrm{patch}}-s_r.
```

如果 clean 与 corrupted 的分数间隔明显非零，可以补充：

```math
\rho=\frac{s_{\mathrm{patch}}-s_r}{s_c-s_r}.
```

该恢复量是相对当前输入对和指标的比例，不是概率。它可能小于 $0$，也可能大于 $1$。当分母接近零、方向不符合预设行为或基准不稳定时，应优先解释原始分数，按预先规定的规则处理样本并报告数量。

汇总多组输入时，说明使用“先求平均效应再求比值”还是“逐对求比值再平均”，两者不相同。不要仅凭一个归一化热图选择机制结论。

## 4. 一个只用于手算的例子

假设某组输入得到以下分数。这些数字是教学设定，不是模型运行结果：

| 运行 | 候选 logit difference |
| --- | --- |
| clean | $3$ |
| corrupted | $-1$ |
| corrupted 加局部 patch | $1$ |

因此， $\Delta s=1-(-1)=2$，而 $\rho=2/(3-(-1))=0.5$。

可以说：“在这组输入、这个替换位置和所选分数下，patch 恢复了 clean / corrupted 分数间隔的一半。”不能据此说该组件负责了一半的模型知识，或者它单独就构成了完整机制。

## 5. 从恢复实验走向机制检验

- **恢复与破坏方向**：clean activation 放入 corrupted 运行，检查能否恢复；反方向替换检查能否破坏。两者的证据不自动等价。
- **替换基线**：真实样本 activation、均值和零向量回答不同的问题；零值未必是“没有信息”的自然状态。
- **组件组合**：单独消融没有效应可能来自冗余路径，多个组件也可能共同必需。不能只按单点效应大小给机制排序。
- **输入变化**：检查其他名字、模板和位置；改变了多个语义因素的输入对，难以支持单一因素的解释。
- **解释范围**：效应支持该干预下的依赖关系，组件中具体携带的内容、使用路径和完整性仍需后续实验。

关于 patching 的实验类型、指标和证据边界，配对阅读 [Zhang 与 Nanda 的方法比较](https://arxiv.org/abs/2309.16042) 与 [Heimersheim 与 Nanda 的教程](https://arxiv.org/abs/2404.15255)，重点看后者第 2—4 节。

## 6. 第一份实验协议

以下是待执行的最小练习，当前没有运行结果。

1. 固定小型预训练模型、tokenizer、精度与库版本，记录模型转换是否处理了权重或归一化；使用评估模式，控制随机性。
2. 选定一种可重复的行为，预先定义输入对、指标和筛选规则；先报告基准效果。随机初始化模型可练习 hook 和形状，但不应被假定已经学会任务。
3. 从少量输入对开始，用独立的留出模板确认效应。明确 token 对齐、特殊 token、padding 和预测位置。
4. 先做自替换检查：将某次运行的 activation 原样放回同一位置，输出应在数值容差内一致。再加入合理的对照替换，核对 hook 的范围。
5. 对所选观察点扫描层和位置，保存每对输入的 $s_c$、 $s_r$、 $s_{\mathrm{patch}}$；报告分组差异与失败样本，再决定是否细化到 head 或路径。
6. 使用 [实验记录模板](../templates/experiment_record.md) 保存实际配置、命令、代码版本和产物。结论只覆盖已执行的模型与输入分布。

本篇的完成标准是能够解释每次替换、基线和分数的含义。候选组件之间如何传递信息，继续见 [回路与 Path Patching](./circuits.md)。
