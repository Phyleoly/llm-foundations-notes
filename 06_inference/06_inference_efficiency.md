# 推理吞吐、延迟与内存

> 状态：提纲

> 前置内容：[KV Cache 与增量解码](./05_kv_cache.md)、[参数量、计算量与显存](../04_transformer/08_parameter_count_and_compute.md)。

本篇要回答：评价生成速度时，应该测量哪些成本，又怎样解释优化效果？

## 1. 性能指标与瓶颈

- 定义首 token 延迟、逐 token 延迟、吞吐与端到端耗时，并固定输入输出长度。
- 对比 prefill 和 decode 的计算、内存访问与缓存开销，避免只报告单一 tokens/s。

## 2. 批处理与缓存管理

- 比较静态 batch 与持续补入请求的 batching 方式，说明吞吐与单请求延迟的权衡。
- 理解分页式 KV 管理的目标；具体调度和服务实现作为延伸，不展开成部署手册。

## 3. 低精度与量化入门

- 区分权重、激活和 KV cache 的 dtype，以及 weight-only 与激活量化的范围。
- 列出 scale、zero point、量化粒度和校准数据需要记录的内容。

## 4. 最小对照实验

- 固定设备、软件版本、batch、序列长度和 warm-up，分别记录延迟、吞吐、显存与质量。
- 将 kernel 优化、缓存管理与改变数值表示的收益分开报告。
